Photo & file storage

When connected, photos and files upload straight into folders that mirror your categories (e.g. Compliance → Machine Calibration, Incidents → Power, Maintenance → [machine name]). If nothing is connected, files are embedded directly in the data instead (max 4MB each). The Google Drive option below also carries the entire data sync (see "Data sync" further down) — one Apps Script setup handles both files and keeping everyone's dashboard up to date, so if you set up cloud sync at all, use Google Drive.

Your folder link points to ID h5zhu16ee70444c254372b6e6b8c8e4dac964 — that's already filled in below as the root folder. Zoho WorkDrive doesn't offer a one-click "paste and deploy" bridge like Google does, so this needs a small Zoho Creator app to relay uploads. It's still free and only needs a few one-time clicks — no manual API keys.

1
In Zoho Creator, create a new blank app (any name, e.g. "TEC Drive Bridge").
2
Under the app's Connections, add a new connection to Zoho WorkDrive and authorize it. Note the connection's link name (e.g. workdrive_connection) — if you use a different name, update it in the script below.
3
Create a Custom Function (Deluge) in the app, delete the placeholder, and paste the script below.
4
Go to the app's Custom API builder → create a new Custom API → set method POST → under Function pick the function you just created → map the request body fields (fileName, mimeType, base64, folderPath, rootFolderId) to the function's inputs → under Response, return the function's raw output as the API response body.
5
Copy the generated Endpoint URL and paste it below as the Web App URL.
6
Heads up: I've written this against Zoho's documented Deluge tasks, but I can't test-run it myself — use "Test connection" and try uploading one real photo first. If the response doesn't come back as plain JSON, revisit the Response mapping in step 4 (it needs to return the function's output unwrapped).
1
Open script.google.com → New project.

6
If you ever edit the script again, you must create a new version under Deploy → Manage deployments, or the old URL keeps running the old code.

This one script does two jobs: it uploads photos/files into your Drive folders, and it stores the shared app data in a single file (TEC_Data_Sync.json) in that same folder so every device stays in sync. You only need this one setup for both.

Data sync — everyone sees the same data

This uses the same Google Drive bridge set up above (Photo & file storage → Google Drive) — there's nothing separate to configure here. Once that bridge URL is saved, every device automatically pulls the latest data every 20 seconds and pushes every change the moment you make it, so everyone's dashboard stays current without clicking anything. If you haven't set up the Google Drive bridge yet, do that first — this card will show "Not connected" until you do.
